# korean-train-reservation — KTX 조회·예약 CLI

[KNHui/korean-train-reservation](https://github.com/KNHui/korean-train-reservation)은 코레일 KTX 잔여석을 조회하고,
원하는 시간대의 열차 한 편을 예약할 수 있는 Python CLI입니다.
수서·동탄·평택지제를 포함한 45개 역 선택지와 직접 입력한 역을 지원합니다.

코레일이 제작하거나 승인한 공식 프로그램이 아닌 비공식 클라이언트입니다.
모바일 API 변경에 따라 기능이 중단될 수 있으며, 실제 예약·결제 연결의 검증 범위는 아래에 명시합니다.

- 기본 모드: 잔여석을 발견하면 터미널에 알리고 종료합니다.
- 자동예약: 명시적으로 선택했을 때 조건에 맞는 열차 한 편을 예약합니다.
- 예약 성공 알림: 텔레그램으로 예약 내역과 결제 안내를 보냅니다.
- 결제·취소: 공식 앱에서 직접 진행합니다.

기존 `reserve_korail.py`·`reserve_srt.py`는 `train_cli.py`와 `reservation.py`로
대체했습니다. SRT 클라이언트와 이메일 알림용 `TRAIN_SMTP_*`·`TRAIN_NOTIFY_TO`는
현재 버전에서 사용하지 않습니다.

## 설치 및 실행

Windows PowerShell 기준입니다. Python 3.11 이상과 Git이 필요합니다.

```powershell
git clone https://github.com/KNHui/korean-train-reservation.git
cd korean-train-reservation
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe train_cli.py
```

가상환경과 패키지가 이미 설치돼 있으면 마지막 명령만 실행하세요.
통합 메뉴를 사용하려면 `train_cli.py`로 실행해야 합니다.

## 로그인 정보 설정

`KTX_ID`와 `KTX_PASSWORD` 환경변수를 우선 사용합니다. 환경변수가 없으면
OS 키링의 KTX 계정을 읽고, 저장된 값도 없으면 실행 중 직접 입력받습니다.

현재 PowerShell 창에서 환경변수를 설정하려면 아래 명령을 실행하세요.
ID·비밀번호를 소스 파일에 적을 필요가 없으며 비밀번호 입력은 화면에 표시되지 않습니다.

```powershell
$env:KTX_ID = Read-Host "코레일 ID"
$env:KTX_PASSWORD = [System.Net.NetworkCredential]::new(
    "", (Read-Host "코레일 비밀번호" -AsSecureString)
).Password

.\venv\Scripts\python.exe train_cli.py
```

두 변수는 현재 창에서 실행하는 프로그램에 적용되며 창을 닫으면 사라집니다.
계정을 PC에 저장하려면 메뉴의 **로그인 설정**을 사용하세요. 인증 성공 후 OS 키링에
저장합니다. 메뉴에서 저장한 계정보다 환경변수가 우선하므로 계정을 변경할 때도 확인하세요.

`.env` 파일은 자동으로 읽지 않습니다. `.env`·`.env.*`·`.runtime/`·가상환경·로그는
`.gitignore`로 제외합니다. GitHub에는 실제 인증 정보가 없는 소스만 올리세요.

## 사용 방법

1. 환경변수를 설정하거나 **로그인 설정**에서 코레일 통합회원 계정을 등록합니다.
2. **역 설정**에서 자주 이용하는 출발·도착역을 선택합니다. **예매 시작**의 출발역·도착역 목록에는 설정한 역만 표시됩니다. 설정 전에는 기본 역 목록(서울·수서·대전·동대구·부산)을 사용합니다.
3. 필요하면 **승객 유형 설정**에서 어린이·경로우대·장애인 승객 입력을 활성화합니다.
4. **예매 시작**에서 날짜·시간·인원·좌석 조건을 지정합니다. 기본은 잔여석 알림입니다.
5. 열차 번호는 선택 사항입니다. 비워 두고 자동예약에 `y`를 입력하면 지정 시간대에서 좌석 조건에 맞는 열차 한 편을 예약합니다. 번호를 입력하면 해당 열차만 대상으로 합니다. 결제는 공식 앱에서 완료합니다.

예매 입력 중 `Esc`를 누르면 이전 단계로 돌아가며, 입력했던 값과 수정 중인 내용이 유지됩니다.
첫 단계에서 `Esc`를 누르거나 입력 중 `Ctrl+C`를 누르면 메뉴로 돌아갑니다.
`Home`/`End`는 입력 내용의 처음/끝으로 커서를 이동하고, 목록에서는 첫/마지막 항목으로 이동합니다.
모든 선택 목록은 맨 위에서 `↑`를 누르면 맨 아래로, 맨 아래에서 `↓`를 누르면 맨 위로 순환합니다.

예매는 KTX로 조회합니다. 성인 인원은 기본으로 입력할 수 있습니다.
텔레그램 설정과 예약·승차권 확인 메뉴도 사용할 수 있습니다. 결제·취소는 공식 앱에서 진행합니다.
새 잔여석 알림은 터미널에 표시됩니다. 자동예약에 성공하면 저장된 텔레그램 봇 토큰·채팅 ID로 예약 내역과 결제 안내를 전송합니다. 예약 응답이 끊겨도 내역 조회로 성공이 확인되면 알림을 보냅니다. 자동 결제는 실행하지 않습니다.
자동예약 시작 시 `텔레그램 예약 성공 알림이 활성화되었습니다.`가 표시되면 저장된 설정을 불러온 상태입니다. 전송 실패 시 터미널에 안내하며 예약 결과와 중복 예약 방지는 유지됩니다. 텔레그램 전송은 철도 HTTP 한도와 별도로 한 번 시도하며 통신 타임아웃은 10초입니다.
코드를 업데이트한 경우 실행 중인 프로그램을 종료하고 다시 실행해야 새 알림 기능이 적용됩니다.

## 조회·예약 제한

`train_cli.py`의 예매 시작과 `reservation.py`는 `reservation_guard.py`의 같은 로직을 사용합니다.

| 항목 | 기본 동작 |
|---|---|
| 실행 모드 | 잔여석 발견 시 터미널에 알리고 종료 |
| 조회 간격 | 기본 15~30초, 예정 간격 10개를 큐로 유지하고 평균에 따라 보정. 통신 오류 시 기본 120초·240초 대기 |
| 조회 한도 | 기본 무제한. 자동예약 성공 또는 알림 모드의 잔여석 발견까지 반복 |
| 실행 시간 | 기본 무제한, Ctrl+C로 직접 중단 |
| 전체 HTTP 한도 | 기본 무제한, 로그인·대기열·내역 조회 등 내부 요청 횟수는 계속 기록 |
| 개별 통신 | 최대 15초 타임아웃 설정, 자동 리디렉션 중단 |
| 오류 | 연속 통신 오류 3회에서 종료, 인증·접근 제한과 알 수 없는 오류는 중단 |
| 실행 준비 오류 | 자동예약·알림 실행의 초기 로그인, 세션 재로그인, 시작 전 예약 내역 확인도 일시적 통신 오류 시 120초·240초 후 재시도하고 3회 실패 시 종료. 실패 단계와 원인 표시 |
| 세션 | 주기적 재로그인 제거. 명시적인 세션 만료 예외에만 1회 재인증 |
| 중복 실행 | 같은 프로젝트 폴더의 조회·예약 작업은 하나만 실행 |
| 예약 | 탐색 시작 전에 기존 예약·발권 내역 확인. 새 잔여석 발견 시 예약 함수를 즉시 호출한 뒤 출력·상태·결과 로그 기록 |
| 예약 응답 불명확 | 대기 간격을 두고 예약·승차권 내역을 두 차례 조회해 해당 열차가 없으면 잔여석 조회·예약 재시도. 내역 조회 오류는 재확인 반복 |
| 결제 | 자동 결제 없음 |

KTX는 `korail-mobile-api`의 DynaPath 인증을 사용합니다. 로그인 내부 요청과 열차 목록의
모든 페이지도 HTTP 횟수에 포함됩니다. 선택적으로 HTTP 상한을 지정하면 이 내부 요청에도 적용됩니다.
서버가 페이지 식별자를 생략하면 마지막 출발 시각을 포함해 이어서 조회하고 중복 열차를 제거합니다.
KTX는 페이지마다 열차·시간·좌석 조건을 확인합니다. 예약 가능한 후보를 발견하면 이후 페이지를
기다리지 않고 예약을 시도하며, 후보가 없는 페이지에서는 다음 페이지를 계속 조회합니다.
알림 모드도 조건에 맞는 잔여석이 있는 페이지에서 즉시 알리고 종료합니다.

조회 간격과 오류 처리 수치는 프로젝트의 기본값입니다. 코레일이 공개한 허용 기준이나 탐지 회피를
보장하는 수치가 아닙니다. 실제 서버의 탐지 기준과 문자 발송 조건은 확인되지 않았습니다.

메뉴 없이 알림 실행 예시 (날짜·구간은 실제 일정으로 바꾸세요):

```powershell
.\venv\Scripts\python.exe reservation.py --dep 서울 --arr 부산 --date 20261001 --time 120000 --until 140000
```

시간대 내 자동예약은 같은 명령 뒤에 `--reserve`를 추가합니다.
조회 결과 순서대로 좌석 조건에 맞는 첫 열차 한 편을 예약하고 종료합니다.
특정 열차만 자동예약하려면 `--reserve --train-number 실제열차번호`를 추가합니다.
기본 승객은 성인 1명, 좌석은 일반실만입니다. `--adults`, `--children`, `--seniors`,
`--disability1to3`, `--disability4to6`으로 인원을 지정하고, `--seat`에는 `general`, `special`,
`general-first`, `special-first`를 지정할 수 있습니다. 잔여석 표시만으로 전체 인원의 좌석 확보를
보장하지는 않습니다. 열차 번호는 조회 결과의 순번이 아니라 실제 열차 번호입니다.

`--interval`(최소 대기, 15초 이상), `--max-interval`(최대 대기, 기본 30초),
`--max-searches`, `--max-minutes`, `--max-requests`로 제한을 조정할 수 있습니다.
예매 메뉴에서도 최소·최대 조회 대기 시간을 입력할 수 있으며 기본값은 15초·30초입니다.
조회 횟수·시간·HTTP 총량은 해당 옵션을 생략하면 각각 무제한입니다. 상한이 필요하면
양수를 지정하세요. 기본 실행은 매진 상태에서 계속 조회하며, 자동예약 성공 또는
알림 모드에서 잔여석 발견 시 종료합니다. Ctrl+C로 직접 중단할 수 있습니다.
접근 제한, 연속 조회 통신 오류 3회, 재인증 한도 초과, 기존 예약 성공 기록은 중단 조건입니다.
예약 실패·불명확한 응답은 내역 재확인 후 계속 시도하며, 예약 오류 종류도 터미널에 표시합니다.
내역 확인 중에는 추가 예약을 보내지 않습니다. 내역 반영 지연 가능성이 있어 두 차례 확인이
중복 예약을 완전히 배제하지는 않습니다. 내역 재확인에도 설정한 시간·HTTP 한도와 Ctrl+C가 적용됩니다.
최대 대기는 최소 대기 이상이어야 합니다. 예를 들어 `--interval 15 --max-interval 120`이면
15~120초 범위에서 대기합니다.

대기 큐에는 앞으로 사용할 간격 10개를 저장합니다. 앞에서 하나를 사용하고 남은 9개의
평균을 계산해, 범위 중간값보다 짧으면 긴 쪽 절반에서, 길면 짧은 쪽 절반에서 새 간격을
무작위로 뽑아 뒤에 추가합니다. 평균이 중간값과 같으면 전체 범위에서 뽑습니다.
초기 10개를 채울 때도 같은 보정을 적용합니다. 이는 예약을 10건 만드는 큐가 아니라
잔여석 조회 사이의 대기 큐이며, 잔여석 발견 시 예약은 바로 시도합니다.
이미 큐에 들어간 간격은 순서대로 사용하므로 보정은 이후 대기에 반영됩니다.
실행 중 다음 대기 시간을 표시하며, 선택적으로 지정한 시간 상한에 도달하면 대기 중에도 종료합니다.
설계 상세는 [조회·재시도 정책](docs/reservation-policy.md)에 기록했습니다.

과거 날짜, 잘못된 시간 범위, 숫자가 아닌 열차 번호는 로그인 전에 거부합니다.
`reservation.py`는 KTX 전용이며 운영사 선택 옵션(`--rail`)은 제거했습니다.

### 기록과 인증 정보

- `.runtime/events.jsonl`: 시각, 작업 종류, 소요 시간, 요청 횟수, HTTP 상태, 예외 종류와 예약 오류의 코드 위치를 기록합니다.
  비밀번호·토큰·카드 번호·원문 응답·요청 URL은 기록하지 않습니다.
- `.runtime/attempts.json`: 예약 호출이 반환되거나 예외가 발생한 뒤 대상 열차의 해시와 상태를 저장합니다.
  성공 기록은 재예약을 막습니다. 불확실한 시도는 재시작 후에도 내역을 재확인하며,
  두 차례 해당 예약이 없으면 `retryable` 상태로 바꿔 다시 시도합니다.
  예약 취소 후에도 자동 해제하지 않습니다. 기록이 남은 열차의 후속 처리는 공식 앱에서 하세요.
  예약 호출 중 프로세스가 강제 종료되면 기록이 남지 않을 수 있습니다. 재실행 전에 공식 앱에서 확인하세요.
  기존 예약 확인은 탐색 시작 시의 내역을 사용하므로 탐색 중 다른 앱에서 만든 예약은 반영되지 않습니다.
  기존 시도 기록·기존 예약·설정한 요청 제한은 계속 적용됩니다. 예약 호출 자체의 입력 검증 오류나 서버 거절은 성공을 보장하지 않습니다.
- 중단되거나 예약 응답이 불명확하면 공식 앱에서 예약·발권 내역과 구입기한을 확인하세요.
- 인증 정보는 `KTX_ID`/`KTX_PASSWORD` 환경변수, KTX OS 키링 순서로 읽습니다.
  없으면 입력받되 자동 저장하지 않습니다.
- 로그인 서버가 `MACRO ERROR`를 반환하면 자동화 접근 제한으로 표시하고 즉시 중단합니다.
  암호화 정보 요청 실패·로그인 거절·응답 형식 오류도 구분하며, 로그에는 정해진 사유만 기록합니다.
  새 인증 방식에서도 접근 제한이 반환되면 재시도하지 않습니다.
- 메뉴의 로그인 설정은 최대 45초·HTTP 4회 안에서 인증 성공을 확인한 뒤 키링에 저장합니다.
  인증에 실패하면 기존 로그인 설정을 유지합니다.

## 역 목록

수서·동탄·평택지제를 포함한 45개 역을 제공합니다.
`김천(구미)`와 `김천구미`는 하나로 표시하며, 기본 즐겨찾기는 서울·수서·대전·동대구·부산입니다.
기존 KTX 즐겨찾기와 직접 입력한 추가 역은 유지됩니다.

이 목록은 기존 선택지의 합집합으로, 최신 전국 정차역 전체 목록은 아닙니다.
목록에 없는 역은 **역 직접 수정**에서 입력할 수 있습니다.

로그인 없이 목록만 출력하려면:

```powershell
python train_cli.py --list-stations
```

## 테스트

```powershell
.\venv\Scripts\python.exe -m unittest discover -s tests -v
```

통신·시간을 모의 처리해 요청 상한, 접근 제한 이후 정지, 세션 만료, 중복 실행,
예약 성공 직후 타임아웃, 재시작 후 중복 예약 방지, 승객·좌석 옵션 전달을 검증합니다.
이 테스트 명령은 실제 로그인·조회·예약·결제를 수행하지 않습니다. 탐지 회피 효과는 검증 대상이 아닙니다.

## KTX 전용 전환 (2026-09-14)

SRT 클라이언트·인증 변수·설정 조회와 `srtgo` 의존성을 제거했습니다.
메뉴 설정은 프로젝트의 `cli_settings.py`에서 제공하며 기존 KTX 역·승객 설정과
텔레그램 키링 저장 위치는 유지합니다. 텔레그램 설정은 저장만 하며
예약 성공 때 알림을 전송합니다. 예전 SRT 승객 옵션만 저장했다면 승객 유형을 다시 설정하세요.
기존 자격 증명 관리자 항목은 삭제하지 않으며 SRT 항목은 읽지 않습니다.
실행 중인 프로그램은 종료 후 다시 실행해야 변경 사항이 적용됩니다.
